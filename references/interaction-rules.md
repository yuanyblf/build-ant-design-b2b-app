# 交互设计规范

## 表单

- 始终提供明确标签，占位文字不能代替标签。
- 新建和编辑表单在桌面端统一使用“字段标签 + 输入控件”同行布局；标签使用固定宽度且禁止换行，控件容器填满剩余宽度并允许收缩，实际控件根据字段内容长度、输入预期和页面布局选择语义宽度。不得因字段名、校验文案或容器宽度意外变成标签在上、控件在下，也不得将短字段控件全局拉满。
- 弹窗、抽屉、基础表单、分步表单和高级表单均遵守同行规则；只有进入窄屏断点后才整体切换为纵向布局，不允许单个字段随机换行。
- 同一表单内标签宽度一致，默认 112px；业务字段名过长时优先优化文案或使用说明 Tooltip，不通过标签折行撑高表单项。
- 为字段记录并实现默认值、校验规则、数据源、组件类型、单选／多选方式和联动规则；不要让这些信息只存在于代码推断中。
- 必填标识保持一致，特殊格式在字段附近说明。
- 语法格式在前端校验，业务约束以服务端结果为准。
- 提交失败后聚焦或滚动到第一个错误字段。
- 提交期间防止重复操作，同时保留失败后的重试路径。
- 独立编辑页和内容较多的抽屉应提供未保存离开提醒。
- 高级表单的操作栏固定在页面底部；为正文预留底部空间，避免遮挡最后一项内容。

## 查询条件

- 桌面端查询区使用四列网格，每行最多四项；按钮组视为一个网格项。超过三个查询字段时默认只显示前三项，并提供“展开／收起”。
- 单个查询项必须保持“字段名称 + 输入控件”同行：标签固定宽度且不换行，控件填满剩余宽度并允许收缩；禁止使用标签在上、控件在下的纵向布局。
- 查询按钮组与查询项垂直居中，按钮顺序固定为“查询”“重置”“展开／收起”，主操作“查询”位于最左侧；页面变窄导致字段折行后，整个按钮组仍靠当前行最右侧对齐。按钮分别使用 `SearchOutlined`、`ReloadOutlined`、`DownOutlined／UpOutlined`，查询为 Primary，重置和展开／收起为 Default；展开／收起不使用 Link Button，并同步维护 `aria-expanded`。
- 查询区内容与表格内容共用同一左边界；查询容器的内边距和标签列不得造成两者视觉错位。
- “展开／收起”属于视图切换，不是提交动作；高频查询场景可将其独立靠右，并与“查询／重置”保持视觉分组。
- 查询条件不使用星号标记必填。
- 用户执行查询时才校验必填查询项；缺失时在对应控件附近展示 Tooltip，解释需要填写的内容，并将焦点移至该控件。
- 日期起止默认使用 Ant Design `DatePicker.RangePicker`，两个端点均允许为空；业务要求必填、禁选日期、最大跨度或默认区间时必须显式配置。
- 查询项的默认顺序与表格列顺序一致，特殊顺序必须有业务理由并在页面说明中登记。

## 左侧竖状树筛选

- 仅当部门、组织、分类等筛选维度具有稳定上下级关系时使用；它是列表筛选器，不是应用菜单，不得替代左侧导航。
- 桌面端采用左树右列表的 Flex 布局，间距 16px；筛选面板宽 240px、白色背景、圆角 8px、内边距上下 16px／左右 12px、阴影 `0 1px 3px rgba(0, 0, 0, 0.06)`。主内容设置 `flex: 1` 和 `min-width: 0`，保证表格横向滚动不被挤坏。
- 面板高度为 `calc(100vh - 160px)`，以 `top: 80px` 吸顶；搜索头和底部新增入口保持可见，只有中间树区域竖向滚动，并禁止横向溢出。
- 搜索框与收起按钮同行，搜索框允许清空，默认占位文字按业务对象写为“请输入部门名称”等。搜索必须递归匹配并保留命中节点的祖先路径；无结果只在树区域展示局部空状态，不清空右侧列表。
- 使用 Ant Design `Tree` 的连线、整行点击和单选模式，不显示叶子图标；使用稳定业务 ID 作为节点键，默认展开第一个业务根节点。长名称单行省略，并通过 Tooltip 展示全文。
- 选择节点后以节点 ID 驱动列表查询并返回可读名称；“全部”节点清除该维度。树筛选改变时回到第一页并清空已选表格行，筛选 ID 同步到 URL；防止旧请求覆盖新选择。
- 节点操作按钮为弱化图标按钮，鼠标悬停或键盘聚焦节点时显示，点击区域不得小于全局最小目标尺寸。按权限从“编辑”“添加子级”“删除”中选取并保持该顺序，无管理权限时整组隐藏；删除使用危险样式并二次确认。菜单和按钮事件必须阻止触发树选择，实际行为通过业务回调完成，不保留 `console.log` 占位。
- 面板底部使用通栏虚线按钮提供“添加部门”等根级新增操作；没有新增权限时隐藏入口，不显示不可用的假操作。
- 收起面板时在主内容左上方预留展开按钮位置，不覆盖查询条件。未选中时 Tooltip 为“展开筛选面板”；已有选择时显示“已筛选「名称」”，并使用主色弱背景提示仍在筛选。
- 收起和再次展开不得丢失搜索词、展开节点和当前选择。加载、空数据、搜索无结果、请求失败和重试状态分别处理；数据刷新后若当前节点失效，应清除筛选并刷新列表。
- 页面宽度不超过 991px 时切换为上下布局，筛选面板与主内容均占满宽度；关键操作和当前筛选状态不得因响应式布局被静默移除。
- 只使用 Ant Design 公开的 `Input`、`Tree`、`Button`、`Tooltip`、`Dropdown` 等 API 和共享 Token；不得依赖 Ant Design 内部 DOM 类名。树数据由业务层注入，组件使用明确 TypeScript 类型。

## 表格

- 列表、筛选区、表格和独立表单默认占满可用内容宽度，页面四周采用同一响应式 Gutter；禁止为页面主容器设置固定像素宽度。列宽、最小宽度、横向滚动、弹窗／抽屉尺寸和阅读型最大宽度属于允许的语义约束。
- 使用稳定的业务标识作为行键。
- 只有在界面明确说明跨页选择时才保留跨页选中项。
- 数字采用一致的对齐方式，并明确单位。
- 行操作提供具体的无障碍名称，例如“编辑订单 1024”。
- 超过配置数量的行操作收纳到“更多”菜单。
- 区分首次无数据、筛选无结果和请求失败。
- 行内操作较稳定时固定在右侧操作列，表头和操作内容均右对齐；横向滚动时保持操作可达。
- 默认一列展示一个明确业务字段。头像、名称、邮箱等内容只有在身份识别等明确业务场景才允许组成复合字段；普通列表必须拆列。
- 表头选择列、普通数据列和固定操作列统一使用 Table `headerBg` Token；排序、悬停等状态可使用对应状态 Token，但不得让固定操作列表头保持白色而其他表头为灰色。
- 根据字段内容长度和当前列宽自动判断溢出；超出时使用省略号，并在 Hover 或键盘聚焦时通过 Tooltip 展示全文。需要核对全文时允许拖拽列宽，分隔线的悬停、激活反馈与输入框边界保持一致。
- 可跳转或打开详情的单元格使用 Link 或链接样式 Button，文案保留明确对象含义。
- 数据列位于左侧并保持只读；导航链接可打开详情，编辑、删除、启停等变更类动作集中在最右侧操作列。空间不足时保留横向滚动，不能让内容遮挡相邻字段或操作列。
- 选择行后在结果工具栏显示批量操作和已选数量；没有选中项时禁用或隐藏批量操作。
- 结果工具栏必须采用“只读文本居左、操作按钮组居右”的分区布局：总数、已选数量、作用范围等信息放左侧，批量操作、新增、导出等按钮放右侧。窄屏折行时按钮组仍整组靠右，不与左侧文本交错。
- 新增、详情和编辑关闭后保留筛选、排序、分页及合理的滚动位置。
- 行内操作仅按实际能力和权限从“详情 → 编辑 → 复制 → 启用／禁用 → 删除”中选择并保持相对顺序；启用与禁用根据状态互斥，删除始终置于最右并使用危险色。超过可见上限时收入“更多”菜单，菜单内仍保持该顺序，并将删除与普通操作视觉分隔。

## 按钮与下拉菜单

- 主按钮承载当前模块唯一的首要动作；一个模块最多使用一个主按钮，不要并列多个同等强调的主按钮。
- 按钮顺序按使用场景决定，不应用全局统一的“主操作在左／右”规则：
  - 弹窗、抽屉底部提交区整体右对齐，按“次要 → 主”排列，例如“取消 → 保存”。
  - 列表查询区整体右对齐，按“主业务动作 → 辅助动作 → 视图切换”排列，例如“查询 → 重置 → 展开”。
  - 表格顶部工具栏整体采用“只读文本居左、操作按钮组居右”；按钮组内将危险／次要动作放在正向主动作之前，示例为“批量删除 → 导出 → 新增”。
  - 表格行内操作按“详情 → 编辑 → 复制 → 启用／禁用 → 删除”排列，删除始终最右并使用危险色。
- 无法判断操作强调级别时优先使用次按钮，避免错误制造视觉焦点。
- 按钮必须覆盖默认、悬停、按下、禁用和加载状态；加载时避免重复提交。
- 文字按钮用于弱化操作，常用于表格操作列。可使用下拉和前置图标按钮；仅用图标时必须保证图形语义可识别，并提供可访问名称和 Tooltip。
- 下拉菜单根据内容选择简单列表、多选、分组、图标项或带说明项；分组使用标题和分割线建立层级，悬停项必须清晰可辨。
- Select 默认使用 Ant Design 公开组件和 `showArrowPaddingInlineEnd` Token（当前为 18px）保留箭头尾部间距；禁止用原生 `select` 或依赖 Ant Design 内部 DOM 重新定位箭头。

## 弹窗

- 在同一列表业务中选择 Modal 前，必须同时核对详情与编辑复杂度；两者无法同时适用 Modal 时，统一提升为 Drawer 或独立页面。
- 少量表单项的提交使用 Modal，并正常展示必填标识。
- 字段说明放在标签附近、帮助文本或 Tooltip 中，明确格式、数据来源或影响。
- 默认 Footer 为“取消”“确认”，整体右对齐，次操作在左、主操作在右；特殊文案和额外按钮必须来自明确业务要求。抽屉底部提交区使用相同规则。

## 操作反馈

- 字段或局部问题使用就地反馈。
- 短暂成功提示使用 Message；需要用户关注上下文的结果使用 Notification。
- 错误信息说明：发生了什么、哪些内容仍然安全、下一步可以做什么。
- 配置开启时展示请求编号，方便客服和研发排查。
- 服务端变更完成前不得提前提示成功。
- 短暂轻提示可使用 Toast；需要用户立即执行一个轻量操作时使用 Snackbar。
- Toast 可按场景使用纯文字、图标、成功、错误、加载或可关闭模式，避免在同一消息中堆叠多种状态。
- Tooltip 最大宽度为 300px，超出后换行，建议文案不超过两行；可展示快捷键，但不能替代控件的可访问名称。

## 危险操作

确认文案必须包含对象名称和影响。批量、高影响或不可逆操作，应按风险提高确认强度。部分失败时说明成功与失败范围，并保留未成功项目的选择状态。

## 加载与异步

结构明确时使用骨架屏；局部短等待使用加载指示；可衡量过程使用进度。后台刷新时保留稳定内容，避免整个页面闪空。防止旧请求覆盖较新的查询结果。

## 无障碍与响应式

保证合理的键盘顺序、清晰焦点、可识别标签、键盘可操作菜单，以及弹窗或抽屉关闭后的焦点回归。不能只依靠颜色表达状态。窄屏下保持任务顺序，表格允许横向滚动，不静默移除关键操作。
